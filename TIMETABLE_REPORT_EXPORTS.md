# Timetable report exports

`GET /api/v1/timetable/versions/{id}/reports.xlsx?kind=both` generates a workbook from the saved timetable version. `kind` accepts `class`, `teacher`, or `both` and defaults to `both`.

The saved timetable workspace exposes this through **Download class and teacher reports**; the button uses the active authenticated session and downloads the server response.

The workbook has a `Version` metadata sheet plus the requested report sheets. `By InstClass` contains each selected instructional class's weekday/period grid, including configured period times and the non-schedulable Lunch / Muster interval. `By Teacher` shows each teacher's saved schedule, class and subject assignments, available free periods, unavailable periods, and lunch. A composite team lesson appears in the report for the team profile and every individual member, using that timetable version's member snapshot. Both views use the version's stored snapshot and placement cells, so later edits to live teacher/class profiles do not rewrite historical report labels or times. The metadata sheet records version identity, revision, status, export timestamp, actor ID and audit-event ID.

Operators and IT Administrators may export drafts and approved versions. Executives can export approved versions only; unavailable or draft versions return 404. Exports do not change the timetable revision or placements. Each successful download adds a `timetable.report.exported` audit event with actor, version, report kind, format, revision and approval state. Responses are sent with `Cache-Control: no-store`.

The browser also provides **Print class report**, **Print teacher report**, and **Print class and teacher reports**. These open a print-ready report from the saved timetable snapshot; users can print it or save it as PDF in the browser. Visual review against the supplied legacy PDFs led to these layout updates: landscape A4, one class or teacher per page, weekdays as rows, five numbered period columns with configured times, the lunch interval displayed as Period 3 with **Lunch / Muster** in each cell, stronger black grid lines, larger day and lesson text, the SPS crest and service lockup at the upper right, and a generated timestamp footer. Long teacher names use a smaller title size so they stay within the header and clear the crest. Stable stored slot codes remain unchanged. Browser PDF is not a server-generated PDF artifact and requires the browser print dialog.

The browser acceptance test checks one-page A4 landscape output, weekday/period grid orientation, configured times, the Period 3 lunch cell, a placed synthetic lesson, the packaged crest and a long teacher heading without overlap or header overflow. It also verifies that the generated PDF has the expected page count and dimensions. This establishes the reviewed structural and typographic contract; exact pixel-for-pixel parity and row-by-row content reconciliation with the supplied PDFs remain open. The existing XLSX API remains available for audited, server-generated workbooks. Published-timetable attendance integration is implemented: scheduled class lookup, IT-managed class mapping, session provenance and manual-session support are covered in [TIMETABLE_PUBLICATION.md](TIMETABLE_PUBLICATION.md).

## Verification coverage

The export API tests open the generated workbook, verify both report sheets, lunch and free-period rows, report content, role restrictions, audit metadata and unchanged timetable revision/placements. The browser acceptance test verifies the print view and generated PDF page dimensions. The CI workflow exercises both alongside the API, migration and browser suites.
