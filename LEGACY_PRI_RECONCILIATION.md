# Legacy `.pri` reconciliation findings

Reviewed 20 November 2026 from the legacy TImeTables source and representative local `.pri` samples. Counts below are aggregate counts; this document intentionally omits personal/resource names and decrypted field values. The source archives were only read by the bounded validator and were not changed. Automated tests exercise import with synthetic archives; no representative legacy archive has been imported into staging.

## Slot and availability interpretation

| Legacy numeric period | Replacement display | Import treatment |
|---:|---|---|
| 1 | P1 | Teaching slot |
| 2 | P2 | Teaching slot |
| 3 | Lunch | Never a teaching slot; report for review |
| 4 | P3 | Teaching slot |
| 5 | P4 | Teaching slot |

The checked legacy availability dialog writes 20 flags in weekday-major order: four teaching periods for Monday, then Tuesday through Friday. Its current source labels those periods 08:30–10:15, 10:15–12:00, 13:25–15:10 and 15:10–16:55; the lunch interval is not one of the four flags. A deterministic helper maps the verified shape to `MON`–`FRI` / `P1`–`P4` during import. Some saved projects contain 25 binary flags. The current resource form iterates every saved flag but has only 20 checkboxes, so positions beyond those controls are ignored; saving then rewrites the profile as 20 flags. That lossy UI behavior is not a verified 25-to-20 conversion rule. The importer therefore requires IT to explicitly confirm using the mapped application teacher's availability for each 25-flag profile; no 25-to-20 conversion is guessed.

Period 3 placements are excluded from lesson occupancy and placed-versus-required totals. A period-3 row with a named teacher is flagged `lesson_in_lunch_slot`. A blank-teacher period-3 row is flagged `lunch_entry_requires_review` so a legacy placeholder is visible and cannot be mistaken for a confirmed lesson. An IT Administrator or Superuser must inspect and explicitly confirm every such source row before import; the source row indexes and count are audited, and confirmed lunch placeholders are excluded from lesson placements. Missing, extra or duplicate confirmations reject the entire import. A period-3 `ALL` row also requires whole-school event mapping and cannot be acknowledged as a blank-teacher placeholder.

## Validation and import boundary

The read-only validator checks archive/member bounds, required and optional encrypted member names, resource references, duplicate class/teacher occupancy, requirement counts, availability shape, R07 period configuration, and special teacher/event mappings. It emits aggregate counts and row-indexed issue codes; it does not expose values by default, mutate the `.pri`, or write to the application database.

## Archive format verification

The legacy source and the 18 November project confirm that `R07.bin` is an optional seventh AES-encrypted JSON member. It contains `DefaultPeriods`, `Clusters` (class assignments and optional custom times), and `ClassOverrides`. The parser requires six core members and accepts R07 only when its structure, five named periods, time ranges, non-overlap and class references are valid. A project without R07 keeps the application's existing period times. For R07, the import form requires explicit confirmation; it preserves each mapped class's effective source times as class-level period overrides before building the draft. It does not change dashboard cluster memberships or create new clusters. Review or set those memberships separately if future shared cluster edits are needed.

IT Administrators and Superusers can run the same bounded preflight from **Legacy timetable preflight** in the application. The browser sends the archive as an in-memory binary upload capped at 10 MiB, matching the reverse proxy limit. The API accepts at most 5,000 rows in each source collection, reads the six encrypted members in memory, returns aggregate counts plus issue codes and 0-based source indexes without labels, and writes a redacted audit event. The UI presents issue locations as 1-based rows. It does not persist the uploaded archive or import any records. Configure `LEGACY_PRI_KEY_HEX` in the protected environment file to enable this feature; leave it unset when legacy preflight is not required. Do not put the key in source control or print it in terminal output.

After the redacted report, IT Administrators and Superusers may explicitly choose **Inspect source labels for mapping**. This separate audited endpoint reveals teacher, subject and class labels, lesson requirements and placed schedule rows so IT can reconcile the row-indexed findings to the source. Names are not written to audit events, and sign-out clears the displayed source data. The archive is still processed in memory and discarded; inspection does not create or change resources.

Each reported source row is a direct control: selecting it performs the audited inspection if needed, opens the matching source table, and focuses/highlights that record. The report initially shows 40 rows per finding and expands the rest on request. Unplaced and overplaced requirement findings carry their associated source requirement rows, so operators can locate the affected weekly counts without guessing from aggregate totals. Duplicate teacher-slot findings identify both the current placement and the earlier placement occupying that slot, with links to inspect both records.

After inspection, IT can map each source teacher, subject and class to an existing application resource. Missing or invalid teacher references can be resolved by selecting the verified application teacher or group for each source requirement or placement; the selected target is then checked against the mapped requirement and shared timetable rules. Composite teacher references require an existing composite group whose member IDs exactly match the mapped source teachers. Each `ALL` placement must map its source subject row to an active class fixed event for the selected academic year. The fixed event's class targets and weekday/period slots must exactly match the source placements; the event definition is snapshotted into the imported draft, and the source event rows are not created as lessons. The mapping audit stores source row indexes and fixed-event IDs without writing event labels. The importer does not create or alter teacher, subject, class, or fixed-event profiles. For R07, explicit confirmation applies effective source times as class-scoped period overrides in the same transaction; period and lesson validation run before the draft commits. Failure rolls back period changes, requirements and draft together. It creates a weekly DRAFT, creates missing lesson requirements transactionally, reuses only exact active matches, packs source periods into configured lesson blocks and validates every placement with the shared timetable rules. Any conflicting requirement, duplicate mapping, schedule clash or incomplete mapping rolls back the whole import.

The import request is processed in memory and is bounded to a 10 MiB archive plus 256 KiB of mapping options. The application stores no `.pri` file; it stores a SHA-256 fingerprint with academic year/week and draft ID. A unique database constraint prevents the same archive from being imported twice for a given week, including concurrent attempts. Audit data contains the fingerprint, aggregate counts, index-to-ID fixed-event mappings, teacher override indexes, R07 period class indexes and confirmed lunch source indexes, never decrypted labels. Imported drafts remain unapproved and unpublished. Assigned-teacher lunch lessons, unconfirmed blank-teacher lunch placeholders, pending/unplaced rows and uncorrected duplicate placements still block import. Confirmed lunch placeholders are excluded rather than imported as lessons. `ALL` whole-school placements are imported only through exact fixed-event mappings. Preserve the original archive in its controlled source location because the application does not back it up.

Synthetic automated tests cover mapping, transaction, validation and duplicate protection. Chromium coverage also imports a synthetic 24-class project, maps all 24 whole-school rows to one exact matching fixed event, and verifies that the result is a draft. A representative source archive still needs a witnessed staging import and row/slot reconciliation before migration sign-off.
